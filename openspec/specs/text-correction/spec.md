# text-correction Specification

## Purpose

Гибридное исправление орфографии, грамматики и пунктуации в тексте: дешёвый алгоритмический этап для явных опечаток и опциональный глубокий этап через LLM. Клиент-агностик: не зависит от Telegram и пригоден для веб-клиента.

## Requirements

### Requirement: Исправление явных опечаток
Система SHALL исправлять без обращения к LLM явные опечатки и пунктуационно-оформительские ошибки: слово с однозначным вариантом правки, отсутствие пробела после знаков препинания, двойные пробелы, строчная буква после точки.

#### Scenario: Однозначная опечатка исправлена
- **WHEN** текст содержит слово с однозначной опечаткой (например, «апелсина»)
- **THEN** система возвращает исправленный текст с корректным словом («апельсина»)

#### Scenario: Двусмысленная опечатка не трогается
- **WHEN** слово допускает несколько равновероятных вариантов правки
- **THEN** система не изменяет это слово и оставляет его для глубокой правки

#### Scenario: Пробел после запятой
- **WHEN** текст содержит «текст,текст» без пробела
- **THEN** система возвращает «текст, текст»

#### Scenario: Двойные пробелы
- **WHEN** текст содержит несколько подряд идущих пробелов
- **THEN** система схлопывает их в один

#### Scenario: Заглавная буква после точки
- **WHEN** после точки в предложении стоит строчная буква
- **THEN** система поднимает её в заглавную

### Requirement: Белый список банвордов
Система MUST NOT изменять слова из списков банвордов и их словарных форм (`TARGET_WORDS`, `WORDS_LEMMA`), даже если словарь языка считает их неизвестными.

#### Scenario: Сленговый банворд не «чинится»
- **WHEN** текст содержит банворд, отсутствующий в словаре языка (например, «нейронка»)
- **THEN** система не изменяет это слово

### Requirement: Глубокая коррекция через LLM
При включённой глубокой коррекции и длине текста не более порога система SHALL передавать текст LLM для исправления грамматики и пунктуации. LLM получает уже исправленный алгоритмом текст и должен вносить минимальные правки, не меняя слова и их порядок.

#### Scenario: Глубокая правка грамматики
- **WHEN** включена глубокая коррекция, текст в пределах порога и содержит грамматическую ошибку («Я иду в школа»)
- **THEN** система возвращает исправленную грамматику («Я иду в школу»)

#### Scenario: Правки минимальны
- **WHEN** LLM исправляет грамматику и пунктуацию
- **THEN** порядок слов и лексика исходного текста сохраняются

#### Scenario: Порог длины превышен
- **WHEN** длина текста превышает порог глубокой правки
- **THEN** система применяет только алгоритмическую правку и помечает, что глубокая правка не применена

### Requirement: Недоступность глубокой правки
Если LLM недоступен или вернул невалидный результат, система SHALL вернуть результат алгоритмической правки и пометить, что глубокая правка не применена.

#### Scenario: Ошибка LLM
- **WHEN** LLM-запрос завершается ошибкой
- **THEN** система возвращает текст после алгоритмической правки с пометкой о недоступности глубокой правки

### Requirement: Кэш результатов коррекции
Система SHALL кэшировать результат коррекции по хэшу входного текста. Повторная коррекция идентичного текста MUST NOT вызывать LLM.

#### Scenario: Повторный текст из кэша
- **WHEN** пользователь отправляет текст, идентичный уже скорректированному
- **THEN** система возвращает закэшированный результат без нового вызова LLM

### Requirement: Структурированный результат
Система SHALL возвращать результат коррекции отдельной структурой, не зависящей от клиента: исправленный текст, количество правок алгоритма, признак применения глубокой правки, примечание. Статистика банвордов не входит в эту структуру.

#### Scenario: Результат не содержит статистики банвордов
- **WHEN** клиент запрашивает коррекцию текста
- **THEN** результат коррекции содержит исправленный текст и метаданные коррекции, но не статистику банвордов

### Requirement: Клиент-агностичность
Система коррекции SHALL работать без зависимости от Telegram и возвращать результат, пригодный для любого клиента (веб, бот).

#### Scenario: Вызов без Telegram
- **WHEN** веб-клиент вызывает коррекцию текста
- **THEN** он получает тот же структурированный результат без каких-либо Telegram-зависимостей
